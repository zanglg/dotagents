# Status (read-only)

1. Locate the requested Feature/task and relevant existing Spec, Design, ADR, research, experiment, implementation record and actual Git/issue state. No Feature is required to report on a supplied task or code change.
2. Compare the latest record with live evidence. Separate verified completed work, current work, pending/blocked tasks, draft proposals and unverified claims. A matching HEAD alone does not validate dirty working files or old test results.
3. Read historical `decisions.md`, `review-log.md`, CHL or baseline records only when relevant. Their absence is not evidence that reviews, approvals or tests passed. Design reviews may exist only in the conversation.
4. Return a concise summary and concrete next actions. Do not modify a progress record, create a status document or handoff, run mutating verification, change approval state or claim completion without evidence. An ongoing implementation can continue after a status answer unless the user paused it.
