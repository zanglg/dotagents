# 技术图表几何、排版与连线规范

与 [配色规范与色值](palette.md) 配套使用。本参考统一不同图中的视觉角色，不强制所有图使用相同画布、布局或卡片尺寸。颜色由色谱定义，几何参数由本参考定义；领域标准或数据编码可以覆盖默认规则，但必须记录映射并在系列图中保持一致。

## 1. 尺寸与缩放基准

以下尺寸以最终显示时的 CSS px 为基准，不是设备物理像素。SVG 中只有在 viewBox 与显示尺寸一一对应时，用户单位才等于这些 px。先确定目标显示宽度或论文刊载宽度，再设置画布及样式。

- 同系列图比较最终呈现的线宽、字号、箭头和间距，不只比较源文件数值。
- 例如宽 1400 单位的图显示为 700 px 时，源文件中 2 单位的线只有 1 px；若最终需要 2 px，应采用 4 单位描边，或在目标尺寸下重新布局。
- 字号、箭头、虚线节奏、间距和线宽应协调缩放。不能只修正描边而忽略其余元素。
- SVG 默认让几何整体缩放；只有确有固定屏幕线宽需求时才使用 `vector-effect="non-scaling-stroke"`，并单独检查箭头和虚线的实际尺寸。
- 论文以刊载宽度、字号 pt 和出版要求校准；不要机械地把屏幕 px 数值当成 pt。
- 默认优先整合为一张图，保留整体关系；先通过重排节点、分组、调整留白及精简重复说明改善布局，不因对象或关系较多就直接拆图。
- 仅在上述调整后，最终尺寸下仍信息过密、连线难以追踪或文字需要过度缩小时，才按子主题拆分。不通过删去关键关系来维持单图；拆分后保留必要的整体概览或跨图引用，并统一同名对象、颜色和关系语义。

## 2. 默认几何参数

| 角色 / token | 默认值 | 用途 |
|---|---|---|
| `stroke.container` | 1 px | 大型分组或背景容器边框 |
| `stroke.card` | 1.5 px | 普通对象卡片边框 |
| `stroke.core` | 2 px | 主题核心卡片边框 |
| `stroke.connector` | 2 px | 普通关系、控制或引用连接线 |
| `stroke.primary-path` | 3 px | 有意强调的主要数据路径 |
| `stroke.guide` | 1 px | 非关键网格、分隔及辅助线 |
| `stroke.focus` | 2 px | 独立选中或焦点外环 |
| `radius.card` | 8 px | 普通及核心卡片圆角 |
| `radius.container` | 12 px | 大型分组圆角 |
| `padding.card` | 16 px | 卡片内容与边框的默认间距 |
| `padding.container` | 24 px | 分组外框与内部内容间距 |
| `gap.content` | 8 px | 卡片内部内容块间距 |
| `gap.cards` | 32 px | 无连线标签时的相邻卡片参考间距 |
| `gap.connector-lane` | 16 px | 平行连线中心线之间的默认距离 |
| `clearance.connector` | 8 px | 连线至无关对象或文字外缘的最小参考净距 |
| `gap.focus-ring` | 3 px | 状态边框与外环之间的可见净距 |
| `arrow.size` | 8 x 8 px | 默认实心三角箭头包围盒 |

- 使用角色级样式或 token；同角色不要混用 1.6、1.8、2.1 等无语义的细小差异。
- 间距优先按 4 px 网格组织；含连线标签时，卡片间距由标签长度、箭头和净距共同决定，32 px 不是硬性上限。
- 普通与核心卡片通常保持相同圆角，通过填充与描边强调，不再无故改变形状。
- 必要边界不能仅因属于分组就画得难以辨认；可以提高至普通边框线宽，并使用足够对比的颜色。
- 默认不用阴影、双重装饰边框或发光。外环用于明确的选中或聚焦，不作为普通核心卡片装饰。
- 内存单元格、表格、矩阵、时序图等可采用直角；同类组件在系列图中保持一致。
- 粗线表示重要性或主要路径，不自动代表吞吐量、带宽或数值。线宽承载定量信息时，应另建比例尺和图例。

## 3. 排版层级

| 角色 | 默认字号 | 字重 |
|---|---:|---:|
| 图标题 | 28 px | 700 |
| 副标题 | 16 px | 400 |
| 分组标题 | 13 px | 600 |
| 卡片标题 | 18 px | 600 |
| 正文 / 关系标签 | 16 px | 400 |
| 注释 / 元数据 | 14 px | 400 |
| 代码 / 地址 / 索引 | 14 px | 400 |

- 这是一套屏幕基准，不要求把已有大图逐项硬改为这些源文件数值。先换算最终尺寸，再在同系列中采用一致层级。
- 正文行高默认约 1.4；关系标签可更紧凑，但不得压线或遮住箭头。标题与正文的块间距默认 8 px。
- 同一系列按角色使用一致的字体与回退链，不要求标题、正文和代码使用同一种字体。默认采用下表的分工；用户、领域或出版规范可以覆盖具体字体，但应保持角色一致。

| 文字角色 | 默认字体回退链 |
|---|---|
| 图标题、分区标题、卡片主标题 | `Georgia, "Times New Roman", serif` |
| 正文、职责描述、关系标签、注释 | `Arial, Helvetica, Inter, sans-serif` |
| 代码、API 函数名、地址、偏移量 | `"Courier New", "SFMono-Regular", "SF Mono", "Roboto Mono", monospace` |

- 字体按系统可用性回退；检查目标语言的字形覆盖、字重支持和实际字宽，不能假设跨平台渲染完全相同。该分工不限定内容语言，中文或混排内容也需验证回退结果。
- 等宽字体只用于实际代码或技术标识，不自动用于架构角色标题，也不为展示字体而添加成员、API 等无关实现细节。
- 标题、正文及辅助文字采用配套色调，标题优先通过字号与字重建立层级。不要再用不同颜色补偿不一致的字号。
- 短概念卡片默认将标题与简短描述作为一个文字块：各行共享水平中轴，整个文字块在卡片内垂直居中，而不是分别围绕卡片中心定位每一行。
- 成员列表、表格和长说明不套用短卡片的居中方式；文字列表和长段落保持左对齐，表格各列按内容类型对齐。分区标题通常左对齐，关系标签按连线方向放置。同类内容保持相同对齐规则。
- 按实际渲染后的文字包围盒检查整体位置及文字到边框的净距，不能仅凭锚点或基线判定居中。允许小幅光学校正，但不逐卡随意偏移；字体回退、字号或换行变化后重新检查。
- 不依赖英文全大写表达层级；分组标题可统一使用全大写，但不将整段正文大写。
- SVG 多行文字需显式安排行距或使用支持的文本布局方式，不能假设设置 CSS `line-height` 就会自动换行。

## 4. 将布线路径与线型语义分开

路径形状回答“怎样连接”，线型回答“是什么关系”，两者不是同一个维度。

- `straight`、`polyline`、`orthogonal`、`curved` 描述几何路径。
- `solid`、`dashed`、`dotted` 描述实线、虚线、点线的语义。
- 实线可以是折线；可选关系也可以沿一条直线路径画成虚线。
- 不因绕开障碍改用虚线，不因关系重要改用曲线，不因返回方向改用点线。

在落笔前建立最小样式映射：对象边框、分组边框、关系线型、线宽角色、箭头方向和标签。只引入图中实际需要的种类。

## 5. 连接线路由顺序

**The connector routing fallback order is: straight → polyline → orthogonal → curved.**

即：**直连 -> 简单折线 -> 正交折线 -> 曲线**。

| 路径 | 定义 | 使用条件 |
|---|---|---|
| Straight | 单一直线段，可水平、垂直或斜向 | 首选；方向明确且不穿过无关对象、文字或箭头 |
| Polyline | 少量直线段组成的折线，允许斜向段 | 直连不可读时，以尽量少的折点绕过障碍 |
| Orthogonal | 所有线段水平或垂直、转角为 90 度 | 简单非正交折线仍碰撞、端口方向受限或需要有组织的布线通道 |
| Curved | 平滑曲线 | 前述方案仍难以辨认，或确需表达自环、回边等且更简单方案不可用 |

数学上正交线也是折线；此处 polyline 特指不强制直角的简单折线，orthogonal 指专用正交通道布线。

执行规则：

1. 先调整节点对齐、端口位置和间距，尝试直连，不为保留任意布局而立即升级复杂路径。
2. 更早的方案若无法同时满足避障、标签空间、方向可辨和成对连线一致性，才尝试下一种。仅为整齐、对称或垂直接入卡片，不足以改用折线；直线无碰撞且方向清晰时，应保留直线。
3. 在同一连线组中协调选择路径，不为每条线独立找最短路径，造成一条直线、一条绕弯的无意差异。
4. 控制折点与绕行长度。普通连接尽量从面对的边进出，避开圆角及文字；正交路径终端沿边界法向接入。
5. 正交转角默认使用一致的圆连接或小幅圆角处理，但仍保留正交通道结构，不把它变成任意曲线。
6. 自环或领域专用布线可以直接采用必要的形态，但说明其约束；不能因为“更好看”而跳过可行的简单方案。

## 6. 两组件间的双向或多条连接

同一对组件存在两条连接时，优先采用**分离、平行、对称且视觉权重一致**的布线，而不是两条线以不同角度汇聚、交叉或互相覆盖。

- 并排组件优先使用上下两条水平通道；上下排列组件使用左右两条垂直通道。
- 斜向组件可使用两条平行斜线，不要求所有图都横平竖直。
- 分别为两条线分配对齐端口；不要把两个方向叠在同一条路径上，或都挤在同一个中心端口。
- 默认通道间距 16 px；若标签、箭头或粗线需要更多空间，应同时扩大间距与端口间距。
- 需要绕行时，两条线采用相同路由家族及协调的折点、拐角和终端方向；主干尽量保持等距，端点附近允许必要调整。
- 端口固定或障碍使严格平行不可行时，优先重排对象；仍不可行才做最小偏离，保留可追踪性，不为追求绝对等长而增加无意义折点。
- 线宽、颜色和箭头大小默认一致。只有关系确有不同语义时才使用不同样式，例如必选请求与可选回退，而不是自动将反向线变淡、变细或改成虚线。
- 同一对连接作为一组执行路由回退顺序，不一条随意画直线、另一条画曲线。

### 两条单向线还是一条双头线

- 两条关系需要各自命名、表示请求与响应、读与写或不同数据时，用两条平行单向箭头，并分别标注。
- 只需表达一个对称的双向通信关系、不区分两个方向的行为时，才可以用一条双头箭头。
- 双头箭头不自动代表同时发生、同步或顺序；这些含义需要文字说明。
- 无方向的关联用无箭头连接线，不用双头箭头代替“无方向”。

## 7. 实线、虚线与点线的语义

默认采用以下映射。若领域标准另有定义，先声明覆盖规则，不把多个标准混用。

| 线型 | 连接线的默认含义 | 使用要求 |
|---|---|---|
| 实线 `solid` | 图中明确建模的关系、调用、引用或数据路径 | 默认样式；不自动意味着物理连接或同步执行 |
| 虚线 `dashed` | 可选、条件成立时才启用或假设中的关系 | 用标签说明具体条件；不要只写“较弱关系” |
| 点线 `dotted` | 注释引导、说明性关联或非执行性的上下文引用 | 默认无流程箭头；不能让人误认为真实数据流 |

### 固定节奏

- 实线：不设置 `stroke-dasharray`。
- 虚线：默认 `stroke-dasharray="6 4"`，`stroke-linecap="butt"`。
- 点线：默认 `stroke-dasharray="0 6"`，`stroke-linecap="round"`，点的直径由线宽决定。渲染器不支持零长度圆点时，用等距圆点实现，不随意换成不同含义的短虚线。
- 节奏按最终尺寸校准，并在同系列中保持一致；非常短的连线若无法显示至少两个可辨识单元，应延长通道或用明确标签表达条件，而不是留下一个无法识别的破折号。
- 普通实线和折线默认采用 `stroke-linecap="butt"`、`stroke-linejoin="round"`；点线的圆端帽是有意的例外。

### 禁止无意义编码

- 不用虚线表示“次要”“离得远”“反向”“更美观”或“颜色不够用”。仅次要但确定存在的关系仍用实线，通过位置、标签或适度视觉层级弱化。
- 不默认用虚线表示异步、点线表示同步；执行时序必须有领域约定或标签。
- 不默认将错误关系改成虚线，因为“错误”与“可选”不是同一维度。保留关系线型，叠加错误色、标签或图标。
- 同一图中不要让虚线同时独立表示可选、异步和远程三种含义。若它们都属于条件性关系，需逐条说明条件，否则更换编码通道。
- 统计图中的线型可用于区分数据系列；通过图例建立映射，不套用架构图的可选关系语义，也不在同一线组中让同一线型承担冲突含义。

## 8. 箭头、交叉与连接点

- 默认箭头为统一大小的实心三角形，颜色与对应连线一致，尖端准确落在目标边界或指定端口，不进入卡片文字区。
- 普通关系与主要路径默认共享 8 x 8 px 箭头，不因线宽变粗而自动放大。若确需更大箭头，建立统一的额外规格并记录用途。
- SVG 默认采用 `markerUnits="userSpaceOnUse"`、`orient="auto-start-reverse"`，将 `refX` / `refY` 对齐箭头尖端。这里固定的是用户空间尺寸，整张图缩放时仍须换算最终大小。
- 虚线或点线的线身不改变箭头形状；箭头本身保持实心。若语义不表示方向，直接不加箭头。
- 箭头前保留清晰的末段方向，不把箭头放在急转角上。连线和箭头轮廓不能覆盖标签。
- 线条交叉默认不表示连接；真正的连接节点使用明确的实心圆点，默认直径 4 px，必要时配标签。
- 优先通过布局和布线路由减少交叉。不可避免的非连接交叉尽量接近直角，不使用连接圆点，也不为了跨线装饰随意增加弧形跳线。
- “点线”的重复圆点与“连接点”是不同符号，不能把点线路径经过的位置理解成多个分支节点。

## 9. 卡片边框与分组底框

边框线型也必须有含义；不能仅因为容器较大、较淡或嵌套较深就改成虚线。

| 线型 | 卡片 / 分组边框的默认含义 | 必要说明 |
|---|---|---|
| 实线 | 图中明确建模的对象或边界 | 默认样式；不自动宣称是物理或部署边界 |
| 虚线 | 可选、条件性、假设或计划中的对象 / 分组 | 明确标注“可选”“假设”“计划中”等适用状态 |
| 点线 | 仅为解释而划出的逻辑集合，无独立对象或执行边界含义 | 标注“逻辑分组”等，不冒充真实部署、安全或隔离边界 |
| 无边框 | 已通过位置、留白和标题明确组织的非关键区域 | 不能用于必须精确辨认的安全、地址或单元格边界 |

- 明确存在的对象即使内容是抽象概念，也不自动使用虚线；抽象程度不是默认虚线语义。
- 虚线容器表示容器本身的条件性，内部确定存在的子对象仍可用实线；不要机械传播父容器的线型。
- 点线逻辑分组可以包含实线对象，并使用浅中性背景。底色不负责替代边界标签。
- 分组边框不带箭头，除非边框本身确实代表某种有向路径，此时应另建图形元素。
- 线型默认节奏与第 7 节一致；边框宽度仍按容器或卡片角色选择，不继承连接线的 2 px。
- 安全域、进程、地址空间等关键边界必须有准确标签与足够辨识度。若领域约定采用虚线，应在图例中说明，不套用“可选”的默认解释。
- 同一图的虚线框与虚线关系应尽量共享“条件性”的上层含义。若线型因领域标准有不同用法，图例应分别说明边界和关系，不能让读者猜测。

## 10. 标签与图例

- 每种非默认线型、特殊箭头或特殊边界在图例或就地标签中有明确解释；不要求给每条普通实线重复添加“实线”说明。
- 标签靠近自己的连线，保持统一侧向偏移，不压在箭头、折点或另一条线上。
- 两条平行线的标签优先放在通道外侧，或错开至各自清晰的区段；不要把两段长文字挤在狭窄的中间空隙。
- 标签需要遮挡线条时使用与实际局部背景匹配的不透明底色，并留少量内边距；不要用白色标签在有色容器上制造无意的白块。
- 卡片内容与连接线标签不重叠；空间不足时移动对象或扩大布局，而不是缩小标签到不可读。

## 11. 示例决策

### 请求与响应

两个并排组件之间：上方实线箭头 A -> B 标“请求”，下方平行实线箭头 B -> A 标“响应”。两者线宽、箭头大小相同，端口分别对齐；不因响应是反向就使用虚线。若响应仅在特定条件下发生，才改为虚线并写出条件。

### 核心数据流与可选回退

主要数据流使用 3 px 实线和普通大小箭头；可选回退使用 2 px 虚线并标“仅失败时”。线宽表达主次，虚线表达条件，方向由箭头表达，三者含义不能混为一谈。

### 实体、可选模块与逻辑分组

确定的组件使用实线框；可选插件使用虚线框并标“可选”；只为讲解划出的集合使用点线底框并标“逻辑分组”。三者不因背景深浅而交换线型。

## 12. 交付检查

交付时使用 [统一验收清单](../SKILL.md#输出与验收)，不另设重复检查项。尺寸、路由、成对连线、线型、端点与碰撞的判定依据为本参考对应章节。
